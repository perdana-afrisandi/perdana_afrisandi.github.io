Telecom Revenue Assurance & Cross-Layer DWH Control Tower

Automated 3-tier reconciliation across Network Usage (CDR), Billing Systems, and Cloud Data Warehouse (UDP) to detect revenue leakage.

Section 01

1. Overview & Business Context

Telecommunications providers process hundreds of millions of daily network events (Call/Data Detail Records - CDRs). Between network switches, rating/charging engines, and analytical Data Warehouses, subtle pipeline drops or catalog sync errors cause subscribers to consume services without being billed (Revenue Leakage) or cause duplicate records to distort executive KPIs.

This project provides a complete, 100% synthetic Telecom Revenue Assurance & Data Reliability Control Tower built with BigQuery SQL and Streamlit.

Section 02

2. Data Sources & Star Schema Modeling

Powered by a custom Python synthetic telecom transaction generator (`streamlit_control_tower.py`) simulating 5,000+ daily audited records across three layers:

  • Layer 1 — Network Usage Logs (CDR): Raw data/voice/VAS session usage recorded by cell towers.
  • Layer 2 — Billing & Charging Ledger: Actual balance deductions and invoiced amounts.
  • Layer 3 — Analytical Cloud DWH (UDP): Downstream reporting fact tables used by Finance and BI.
Section 03

3. Data Quality & Technical Challenges Solved

  • Multi-Layer Volume Scale: Joining raw network logs against billing tables requires partitioned, pre-aggregated CTEs to avoid excessive query slot consumption.
  • Distinguishing Leakage from Free Promos: Separating true unbilled network sessions from valid zero-rated bonus quota usage.
  • Cross-Platform Migration Parity: Ensuring legacy on-prem (Impala) and modern cloud (BigQuery) storage layers maintain 100% row and sum parity.
Section 04

4. Analytical Walkthrough & SQL Implementation

  • Step 1 — Automated 5-Rule SQL Validation Suite: Executed daily checks for Null MSISDN (DQ-01), Duplicate Transaction IDs (DQ-02), Unbilled CDRs (RA-01), Undercharged Tariffs (RA-02), and DWH Sync Delays (DE-01).
  • Step 2 — Streamlit Technical Control Tower: Built an interactive web app allowing engineers to filter anomalies by Region, Brand, and Product.
  • Step 3 — Executive Financial Impact Matrix: Quantified exact Rupiah exposure per root cause to prioritize engineering bug fixes.
-- Production SQL Validation & Analytical Query
SELECT c.trx_date, c.product_code,
       CASE WHEN c.msisdn IS NULL THEN 'DQ_01_NULL_MSISDN'
            WHEN b.row_cnt > 1 THEN 'DQ_02_DUPLICATE_TRX'
            WHEN b.trx_id IS NULL THEN 'RA_01_UNBILLED_CDR_LEAKAGE'
            WHEN c.cdr_amount > b.billed_amount THEN 'RA_02_UNDERCHARGED_TARIFF'
            ELSE 'MATCHED_VALID' END AS audit_flag,
       COUNT(*) AS trx_count,
       SUM(c.cdr_amount - COALESCE(b.billed_amount, 0)) AS revenue_discrepancy_idr
FROM `synth_telco.vw_cdr_agg` c
LEFT JOIN `synth_telco.vw_billing_agg` b ON c.trx_id = b.trx_id
GROUP BY 1, 2, 3;
Section 05

5. Key Takeaways & Quantified Business Impact

  • Detected a simulated 2.2% unbilled CDR leakage gap and 1.3% tariff undercharge anomaly concentrated in Digital VAS subscriptions.
  • Reduced anomaly detection time (MTTD) from end-of-month closing to daily T+1 automated morning audits.
  • Provided an auditable SQL reconciliation framework ready for both daily Revenue Assurance and cloud DWH migration sign-off.
